1. Python essentials for this course

Dictionaries map keys to values. defaultdict gives you a default value for missing keys, which is handy for counting.

counts = {}
for w in ["a", "b", "a"]:
    counts[w] = counts.get(w, 0) + 1
# {'a': 2, 'b': 1}

from collections import defaultdict
d = defaultdict(int)
for w in ["a", "b", "a"]:
    d[w] += 1

List comprehensions build lists in one line. Dict comprehensions do the same for dicts.

squares = [x*x for x in range(5) if x % 2 == 0]   # [0, 4, 16]
inv = {v: k for k, v in {"a": 1, "b": 2}.items()}  # {1: 'a', 2: 'b'}

Lambda and sorting. sorted takes a key function.

names = ["Alan Turing", "Ada Lovelace"]
sorted(names, key=lambda s: s.split()[-1])   # sorts by last name

zip and enumerate pair up items from several sequences or give you indices.

for i, (a, b) in enumerate(zip([1, 2], ["x", "y"])):
    print(i, a, b)

Nested data: lists of dicts (or dicts of lists) are the standard shape for records. Loop over them, or convert them to a pandas DataFrame.

2. Big-O and running time

Asymptotic running time describes how work grows with input size n. A single loop over the data is O(n). A loop inside a loop is O(n²). A dict lookup is O(1) on average, so replacing a nested search with a dict is often the fix for a slow solution.

3. Floating-point numbers

Computers store most decimals in binary floating point, so some values can't be represented exactly. That's why this is False:

0.1 + 0.2 == 0.3          # False
abs((0.1 + 0.2) - 0.3)   # about 5.5e-17

Compare floats with a tolerance, not ==. Use math.isclose or np.isclose. Be careful with subtracting nearly equal numbers and adding very large and very small numbers, since these lose precision.

4. Regular expressions

A regex is a pattern for matching text. The basics are \d (digit), \w (word character), \s (whitespace), . (any character), + (one or more), * (zero or more), ? (optional), [abc] (a character class), ^ and $ (start and end), and ( ) (groups).

import re
re.findall(r"\d+", "a12 b345")                 # ['12', '345']
re.search(r"(\w+)@(\w+\.\w+)", "me@site.com").groups()   # ('me', 'site.com')
re.sub(r"\s+", " ", "too    many   spaces")     # 'too many spaces'

Test patterns interactively at regex101.com with the Python flavor selected.

5. Pandas

A DataFrame is a table. A Series is one column. The core operations are selecting, filtering, grouping, and joining.

import pandas as pd
df = pd.DataFrame({"team": ["A", "A", "B"], "pts": [10, 14, 7]})

df.loc[df["pts"] > 8, ["team", "pts"]]   # label-based select with a boolean filter
df.iloc[0:2, 1]                          # position-based select
df.groupby("team")["pts"].mean()         # A: 12.0, B: 7.0
df.merge(other, on="team", how="left")   # join (SQL-style)
df.melt(id_vars="team")                  # wide to long

Tip: loc uses labels and includes the end of a slice. iloc uses positions and excludes the end.

6. NumPy

NumPy arrays are fixed-type, vectorized containers. Operations apply to the whole array at once, which is much faster than Python loops.

import numpy as np
A = np.array([[1., 2.], [3., 4.]])
A.shape            # (2, 2)
A @ A              # matrix multiplication
A * A              # element-wise
A[A > 2]           # boolean mask -> [3. 4.]
A - A.mean(axis=0) # broadcasting: subtracts column means from every row
np.argsort(-A[:, 0])  # indices that sort column 0 in descending order

Broadcasting rule: shapes are compared from the right. Each pair of dimensions must match or one must be 1. Then the size-1 dimension is stretched to fit.

7. SQL

The core pattern is SELECT, FROM, WHERE, GROUP BY, HAVING, ORDER BY. SQL runs in this order: FROM, WHERE, GROUP BY, HAVING, SELECT, ORDER BY. That's why you can't use a SELECT alias in WHERE.

SELECT team, AVG(pts) AS avg_pts
FROM games
WHERE season = 2025
GROUP BY team
HAVING AVG(pts) > 10
ORDER BY avg_pts DESC;
  • JOIN: INNER keeps matches only. LEFT keeps every row from the left table.
  • NULL: use IS NULL, not = NULL. COALESCE(x, 0) replaces NULL.
  • CASE: conditional values, e.g. CASE WHEN pts > 10 THEN 'high' ELSE 'low' END.
  • CTE: WITH t AS (SELECT ...) SELECT ... FROM t, a named subquery.
  • Window functions: RANK() OVER (PARTITION BY team ORDER BY pts DESC) ranks within groups without collapsing rows. LAG and LEAD look at neighboring rows.

8. Linear algebra (the parts you'll actually use)

  • Vector: a list of numbers. The dot product multiplies matching entries and sums them: x · y = Σ xᵢyᵢ.
  • Matrix multiplication: (m×n) times (n×p) gives (m×p). The inner dimensions must match. Each output entry is a row dotted with a column.
  • Transpose: swap rows and columns. (AB)ᵀ = BᵀAᵀ.
  • Norm: the length of a vector. The L2 norm is sqrt(x · x).
  • Linear regression: solve min ||Ax - b||². This is where QR decomposition comes in.
  • Eigenvectors and SVD: these describe the directions a matrix stretches the most. SVD underlies PCA and compression.

Best free visual intro: 3Blue1Brown's "Essence of Linear Algebra" series. For a full course, use LAFF (ulaff.net), which the instructors recommend.

9. Probability and statistics

  • Mean is the average. Median is the middle value and is robust to outliers.
  • Variance is the average squared distance from the mean. Standard deviation is its square root.
  • Conditional probability: P(A | B) = P(A and B) / P(B).
  • Bayes' rule: P(A | B) = P(B | A) P(A) / P(B).
  • Correlation measures linear association. It is not causation.

10. Calculus for optimization

A derivative tells you how fast a function changes. Machine learning minimizes a loss function. Gradient descent repeats: compute the gradient, then step the other way.

w = w - learning_rate * gradient   # repeat until the loss stops falling

The gradient is the vector of partial derivatives. The learning rate controls step size. Too big and you overshoot. Too small and you crawl.

11. Intro analytics glossary (for your current class)

  • Descriptive: what happened. Predictive: what will happen. Prescriptive: what to do about it.
  • Train / test split: fit on one part of the data, evaluate on held-out data.
  • Overfitting: the model memorizes training noise and does badly on new data.
  • Regression predicts a number. Classification predicts a category.
  • Feature: an input column. Target / label: what you're predicting.
  • Outlier: a value far from the rest. Check whether it's an error before removing it.

Concept ladder: what you need to excel

Each concept has the question it answers, the core idea, what you should be able to do, and suggested study hours. Tick a box when you can explain it and solve a problem without notes. Hours are estimates for going from "I've seen this" to "I can do it on the quiz."

Classification (k-nearest neighbors) · 3 h

Question: which group does a new item belong to?
Core idea: k-NN finds the k closest labeled examples and takes a vote. Distances depend on scale, so standardize features first.
Be able to: choose k, explain small-vs-large k tradeoffs, and say why scaling matters.
Resources: ISLR Ch. 4 (free at statlearning.com).

Validation · 3 h

Question: will this model work on new data?
Core idea: split into training, validation, and test sets. k-fold cross-validation averages performance across folds. Never tune on the test set.
Be able to: set up a 5-fold split and explain why the test set stays untouched.
Resources: ISLR Ch. 5.

Clustering (k-means) · 2 h

Question: which items naturally group together without labels?
Core idea: k-means alternates between assigning each point to its nearest center and moving each center to the mean of its points. Results depend on starting centers and on k.
Be able to: walk through two iterations by hand on 6 points.
Resources: ISLR Ch. 12.

Change detection (CUSUM) · 2 h

Question: when did the process start to shift?
Core idea: accumulate deviations from the target, minus an allowance. Signal when the running sum crosses a threshold. The allowance and threshold control how fast you detect shifts and how many false alarms you get.
Be able to: compute a CUSUM table for a short series.
Resources: NIST/SEMATECH e-Handbook of Statistical Methods, process monitoring chapter (free at itl.nist.gov/div898/handbook).

Time series (decomposition, exponential smoothing, ARIMA) · 5 h

Question: what comes next, given trend and seasonality?
Core idea: decompose a series into level, trend, seasonality, and remainder. Exponential smoothing gives recent observations more weight. ARIMA models autocorrelation after differencing to remove trend. ACF and PACF plots help choose its orders.
Be able to: read an ACF plot, say whether differencing is needed, and explain what a smoothing parameter does.
Resources: Forecasting: Principles and Practice (FPP3), free at otexts.com/fpp3, exponential smoothing and ARIMA chapters.

Regression (linear and logistic) · 3 h

Question: how does the outcome change with each predictor?
Core idea: a coefficient is the change in y per unit of x, holding other predictors fixed. Logistic regression models a probability for a 0/1 outcome. Check residuals, p-values, and correlated predictors.
Be able to: interpret a coefficient in words, including for logistic regression on the odds scale.
Resources: ISLR Ch. 3 and 4.

Tree-based models (CART, random forests) · 3 h

Question: what rules predict the outcome?
Core idea: a tree splits the data on the variable and cutoff that best separate outcomes, and pruning limits overfitting. A random forest averages many trees, each trained on a bootstrap sample with a random subset of predictors.
Be able to: explain why one tree overfits and a forest doesn't, and what variable importance measures.
Resources: ISLR Ch. 8; StatQuest's videos on decision trees and random forests.

Variable selection (stepwise, LASSO, ridge) · 3 h

Question: which predictors should stay in the model?
Core idea: stepwise adds or removes variables by a criterion such as AIC. LASSO's penalty can shrink some coefficients to exactly zero. Ridge shrinks all coefficients but keeps them all.
Be able to: say which method would drop variables and which would keep all of them.
Resources: ISLR Ch. 6.

Design of experiments · 4 h

Question: which factors matter, and do they interact?
Core idea: randomize, replicate, and block. Factorial designs estimate main effects and interactions from the same runs. ANOVA tests whether group means differ.
Be able to: read a 2×2 interaction table and say whether the effect of one factor depends on the other.
Resources: NIST/SEMATECH e-Handbook, design of experiments chapter.

Probability distributions · 3 h

Question: how likely is this outcome?
Core idea: binomial counts successes in n trials. Poisson counts events per interval. Exponential models time between events. Normal describes averages and sums. Know their means and variances.
Be able to: set up a binomial probability by hand. Use z-values without a calculator: 1.645 (90%), 1.96 (95%), 2.576 (99%).
Resources: MIT OCW 18.05 readings (see Resources tab).

Probability-based models (Bayes, naive Bayes) · 2 h

Question: how should I update a belief when I see new evidence?
Core idea: posterior = likelihood × prior ÷ evidence. Naive Bayes assumes features are independent given the class.
Be able to: solve a two-test Bayes problem by hand.
Resources: MIT OCW 18.05.

Simulation · 3 h

Question: what is the distribution of an outcome when the formulas get messy?
Core idea: generate random inputs many times (Monte Carlo) and summarize the results. Discrete-event simulation (for example, a queue) moves through events in time order. More replications give a more precise estimate.
Be able to: explain why you need more replications for a narrower confidence interval.
Resources: SimPy documentation tutorial at simpy.readthedocs.io.

Optimization (linear and integer programming) · 4 h

Question: which decision best meets the goal within the limits?
Core idea: decision variables, one objective, and constraints. Integer variables model yes/no decisions. Shadow prices show how much an extra unit of a limited resource is worth. You don't need the simplex math.
Be able to: formulate a small problem on paper and write it in PuLP.
Resources: PuLP documentation at coin-or.github.io/pulp.

Data preparation: missing data and outliers · 3 h

Question: what do I do with blanks and extreme values?
Core idea: first decide whether the data is missing at random or depends on other values. Options include dropping rows, mean or median imputation, and model-based imputation. For outliers, use the IQR or z-scores, then investigate before deciding to remove or transform (log transform for skew).
Be able to: justify one imputation choice and one outlier decision in a sentence each.
Resources: ISLR Ch. 2 covers the general framework; the course lessons are the main source here.

Principal component analysis (PCA) · 3 h

Question: can many correlated variables be summarized with fewer?
Core idea: principal components are orthogonal directions of maximum variance. Standardize first. A scree plot shows how many components to keep. This links directly to SVD in CSE 6040 Topic 15.
Be able to: say what proportion of variance the first two components explain, given their eigenvalues.
Resources: ISLR Ch. 12; 3Blue1Brown's linear algebra series for the geometry.

Advanced models (Week 11 lessons) · 3 h

Question: depends on the model. The syllabus lists this topic by name only, so use your Week 11 lesson list as the authority.
Core idea: for general reference, ISLR Ch. 9 covers support vector machines and Ch. 10 covers neural networks.
Be able to: state what the model is for, what data it needs, and one case where it fails.
Resources: ISLR Ch. 9–10 (statlearning.com).

Modeling judgment and ethics (cases and conceptual questions) · 2 h

Question: is this model appropriate, and is the conclusion reasonable?
Core idea: the course's second stated goal is to evaluate someone else's analysis. Check that the model fits the question and data, and say what the model cannot tell you (causation, extrapolation beyond the data, bias in the data).
Be able to: critique a short case in a paragraph: strengths, one flaw, one fix.
Resources: the three discussion cases in Weeks 12–14.
